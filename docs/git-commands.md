# دستورات Git

در این سند، دستورات Git که در طول توسعه این پروژه استفاده شدند، به همراه توضیح، نحوه استفاده و زمان استفاده از هر کدام آورده شده.

## git init

### توضیح

دستور `git init` برای ایجاد یک مخزن (Repository) جدید در پروژه استفاده میشود.

با اجرای این دستور، یک پوشه مخفی به نام `.git` در پروژه ایجاد میشود که Git اطلاعات مربوط به تاریخچه پروژه، Commitها، Branchها و تنظیمات مخزن را در آن نگهداری میکند.

### نحوه استفاده

```bash
git init
```

### زمان استفاده

در ابتدای پروژه، زمانی که قصد داشتیم پروژه را تحت مدیریت Git قرار دهیم.

- این دستور فقط یک بار برای هر پروژه اجرا می‌شود.
- حذف پوشه `.git` باعث می‌شود پروژه دیگر یک Git Repository نباشد.

## git status

### توضیح

دستور `git status` وضعیت فعلی پروژه را نمایش میدهد.

این دستور مشخص میکند:

- چه فایل‌هایی تغییر کرده‌اند.
- چه فایل‌هایی به Staging Area اضافه شده‌اند.
- چه فایل‌هایی هنوز توسط Git دنبال (Track) نمیشوند.

### نحوه استفاده

```bash
git status
```

### زمان استفاده

قبل از اجرای `git add` یا `git commit` برای بررسی وضعیت فایل‌های پروژه.

### کاربرد در این پروژه

قبل از هر Commit از این دستور استفاده کردم تا مطمئن شوم فقط فایل‌های موردنظر Stage شده‌اند.

- این دستور هیچ تغییری در پروژه ایجاد نمی‌کند.
- فقط وضعیت فعلی Repository را نمایش میدهد.

## git add

### توضیح

دستور `git add` برای اضافه کردن فایل‌ها یا تغییرات به **Staging Area** استفاده میشود.

فایل‌هایی که در Staging Area قرار میگیرند، در Commit بعدی ذخیره خواهند شد. تا زمانی که فایل‌ها را با `git add` به Staging Area اضافه نکنیم، Git آن‌ها را در Commit ثبت نمیکند.

### نحوه استفاده

اضافه کردن یک فایل:

```bash
git add App.jsx
```

اضافه کردن همه فایل‌های تغییر کرده:

```bash
git add .
```

### کاربرد در این پروژه

بعد از اعمال تغییرات روی پروژه، از این دستور استفاده کردم تا فایل‌های موردنظر را برای Commit آماده کنم.

### نکات

- دستور `git add .` تمام فایل‌های جدید و تغییر کرده را به Staging Area اضافه میکند.
- میتوان به جای همه فایل‌ها، فقط فایل‌های موردنیاز را Stage کرد.
- اجرای `git add` به معنای ثبت تغییرات نیست؛ فقط آن‌ها را برای Commit آماده میکند.

## git commit

### توضیح

دستور `git commit` برای ثبت تغییراتی استفاده میشود که قبلاً با `git add` به Staging Area اضافه شده‌اند.

هر Commit مانند یک **نقطه ذخیره (Snapshot)** از پروژه است که میتوان در آینده به آن مراجعه کرد، تغییرات را بررسی کرد یا در صورت نیاز به آن بازگشت.

### نحوه استفاده

ثبت تغییرات همراه با یک پیام:

```bash
git commit -m "Add dark mode feature"
```

### کاربرد در این پروژه

بعد از اینکه تغییرات موردنظر را با `git add` به Staging Area اضافه کردم، از این دستور برای ثبت آن‌ها در تاریخچه پروژه استفاده کردم.

### نکات

- هر Commit باید فقط شامل یک تغییر یا Feature مشخص باشد.
- پیام Commit باید کوتاه، واضح و توصیف‌کننده تغییرات باشد.
- قبل از اجرای `git commit` باید فایل‌های موردنظر با `git add` به Staging Area اضافه شده باشند.

## git branch

### توضیح

دستور `git branch` برای مدیریت Branchهای یک Repository استفاده میشود.

با استفاده از این دستور می‌توان Branchهای موجود را مشاهده، Branch جدید ایجاد و Branchهای اضافی را حذف کرد.

ا Branch این امکان را میدهد که بدون تأثیر گذاشتن روی Branch اصلی (معمولاً `main`)، روی یک Feature یا Bug Fix جدید کار کرد.

### نحوه استفاده

نمایش Branchهای موجود:

```bash
git branch
```

ایجاد Branch جدید:

```bash
git branch feature/dark-mode
```

حذف یک Branch:

```bash
git branch -d feature/dark-mode
```

### کاربرد در این پروژه

برای توسعه هر Feature جدید، ابتدا یک Branch جداگانه ایجاد کردم تا تغییرات آن Feature از Branch اصلی (`main`) مستقل باشد.

### نکات

- ایجاد Branch به تنهایی باعث جابه‌جایی به آن Branch نمی‌شود.
- برای رفتن به Branch جدید باید از `git switch` یا `git checkout` استفاده کرد.
- استفاده از Branchهای جداگانه باعث میشود توسعه Featureها و رفع باگ‌ها منظم‌تر و ایمن‌تر انجام شود.

## git switch

### توضیح

دستور `git switch` برای جابه‌جایی بین Branchها استفاده میشود.

همچنین میتوان با استفاده از این دستور، یک Branch جدید ایجاد کرد و همزمان به آن Branch منتقل شد.

### نحوه استفاده

جابه‌جایی به یک Branch موجود:

```bash
git switch main
```

ایجاد یک Branch جدید و جابه‌جایی به آن:

```bash
git switch -c feature/dark-mode
```

### کاربرد در این پروژه

برای جابه‌جایی بین Branchهای مختلف پروژه و همچنین ایجاد Branchهای جدید برای توسعه Featureهای جدید از این دستور استفاده کردم.

### نکات

- این دستور فقط برای کار با Branchها استفاده میشود.
- برای ساخت Branch جدید و ورود به آن می‌توان از گزینه `-c` استفاده کرد.
- این دستور نسخه جدیدتر و خواناتر `git checkout` برای مدیریت Branchها است.

## git checkout

### توضیح

دستور `git checkout` برای جابه‌جایی بین Branchها، ایجاد Branch جدید و همچنین بازگردانی فایل‌ها به نسخه‌های قبلی استفاده میشود.

در نسخه‌های جدید Git، برای خوانایی بیشتر، بخشی از وظایف این دستور به `git switch` و `git restore` منتقل شده است.

### نحوه استفاده

جابه‌جایی به یک Branch:

```bash
git checkout main
```

ایجاد Branch جدید و جابه‌جایی به آن:

```bash
git checkout -b feature/dark-mode
```

### کاربرد در این پروژه

در این پروژه بیشتر از دستور `git switch` استفاده کردم، اما `git checkout` نیز همان قابلیت جابه‌جایی بین Branchها را دارد.

### نکات

- ا `git switch` جایگزین مناسب‌تری برای جابه‌جایی بین Branchها است.
- ا `git checkout -b` معادل `git switch -c` است.
- در نسخه‌های جدید Git، برای خوانایی بیشتر پیشنهاد میشود از `git switch` و `git restore` استفاده شود.

## git remote add origin

### توضیح

دستور `git remote add origin` برای اتصال Local Repository به یک Repository راه دور (Remote Repository) استفاده میشود.

با اجرای این دستور، آدرس Repository موجود در GitHub به پروژه اضافه میشود تا بتوان تغییرات را بین پروژه محلی و GitHub جابه‌جا کرد.

### نحوه استفاده

```bash
git remote add origin https://github.com/username/repository.git
```

### کاربرد در این پروژه

بعد از ایجاد Repository در GitHub، از این دستور برای اتصال Local Repository به Repository موجود در GitHub استفاده کردم.

### نکات

- این دستور معمولاً فقط یک بار برای هر پروژه اجرا می‌شود.
- ا `origin` نام پیش‌فرض Remote Repository است، اما میتوان از نام‌های دیگری نیز استفاده کرد.
- بعد از اتصال، می‌توان با استفاده از دستورات `git push` و `git pull` تغییرات را با GitHub همگام‌سازی کرد.

## git push

### توضیح

دستور `git push` برای ارسال Commitهای موجود در Local Repository (Local Repository) به Repository راه دور (Remote Repository) استفاده میشود.

با استفاده از این دستور، تغییراتی که به صورت Local ثبت شده‌اند، در GitHub نیز قرار میگیرند.

### نحوه استفاده

ارسال تغییرات به Branch اصلی:

```bash
git push origin main
```

اولین Push برای یک Branch جدید:

```bash
git push -u origin feature/dark-mode
```

### کاربرد در این پروژه

بعد از ثبت تغییرات با `git commit`، از این دستور برای ارسال Commitها به Repository موجود در GitHub استفاده کردم.

### نکات

- قبل از اجرای `git push` باید حداقل یک Commit ایجاد شده باشد.
- این دستور فقط Commitها را ارسال میکند، نه تغییراتی که هنوز Commit نشده‌اند.
- گزینه `-u` باعث میشود ارتباط بین Branch محلی و Branch راه دور برقرار شود و در Pushهای بعدی فقط با دستور `git push` بتوان تغییرات را ارسال کرد.

## git pull

### توضیح

دستور `git pull` برای دریافت آخرین تغییرات از Remote Repository و اعمال آن‌ها در Branch فعلی استفاده میشود.

این دستور تغییرات موجود در GitHub را دریافت کرده و با Branch محلی ادغام (Merge) میکند تا پروژه به آخرین نسخه به‌روزرسانی شود.

### نحوه استفاده

دریافت آخرین تغییرات از Branch اصلی:

```bash
git pull origin main
```

اگر Branch محلی قبلاً به Remote متصل شده باشد:

```bash
git pull
```

### کاربرد در این پروژه

قبل از شروع توسعه یک Feature جدید، از این دستور استفاده کردم تا مطمئن شوم Branch محلی من با آخرین تغییرات موجود در GitHub همگام است.

همچنین بعد از Merge شدن یک Feature، از این دستور برای دریافت آخرین نسخه پروژه استفاده کردم.

### نکات

- قبل از شروع توسعه یک Feature جدید، بهتر است ابتدا `git pull` اجرا شود.
- این دستور تغییرات جدید را از Remote Repository دریافت کرده و با Branch فعلی ادغام میکند.
- اگر بین تغییرات محلی و تغییرات Remote تداخلی وجود داشته باشد، ممکن است Merge Conflict ایجاد شود.

## git log --oneline

### توضیح

دستور `git log --oneline` برای نمایش تاریخچه Commitهای پروژه به صورت خلاصه استفاده میشود.

در این حالت، هر Commit در یک خط نمایش داده میشود و شامل شناسه کوتاه (Short Hash) و پیام Commit است. این نمایش، خواناتر از خروجی کامل `git log` است و برای مرور سریع تاریخچه پروژه بسیار کاربرد دارد.

### نحوه استفاده

```bash
git log --oneline
```

### کاربرد در این پروژه

برای مشاهده تاریخچه Commitها، بررسی تغییرات ثبت‌شده و پیدا کردن Commit موردنظر از این دستور استفاده کردم.

### نکات

- هر Commit دارای یک شناسه (Hash) منحصربه‌فرد است.
- گزینه `--oneline` خروجی را به صورت خلاصه و خوانا نمایش می‌دهد.
- این دستور هیچ تغییری در پروژه ایجاد نمی‌کند و فقط تاریخچه Commitها را نمایش میدهد.

## git reset --soft HEAD~1

### توضیح

دستور `git reset --soft HEAD~1` برای بازگرداندن آخرین Commit استفاده میشود، بدون اینکه تغییرات فایل‌ها از بین بروند.

با اجرای این دستور، آخرین Commit حذف میشود، اما تمام تغییرات آن همچنان در **Staging Area** باقی میماند و میتوان دوباره آن‌ها را Commit کرد.

### نحوه استفاده

```bash
git reset --soft HEAD~1
```

### کاربرد در این پروژه

زمانی که آخرین Commit را با پیام اشتباه ثبت کردم یا متوجه شدم باید تغییرات بیشتری به همان Commit اضافه کنم، از این دستور استفاده کردم تا Commit حذف شود اما تغییرات حفظ شوند.

### نکات

- این دستور فقط آخرین Commit را حذف میکند.
- تغییرات فایل‌ها حذف نمیشوند.
- تمام تغییرات در Staging Area باقی میماند.
- بعد از اجرای این دستور میتوان دوباره با یک پیام جدید Commit ایجاد کرد.
